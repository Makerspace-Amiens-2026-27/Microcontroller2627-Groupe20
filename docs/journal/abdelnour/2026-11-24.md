## 2. Organisation du projet

Nous avons organisé le projet PlatformIO avec la structure suivante :

```text
test_blink/
│
├── include/
│   ├── config.h
│   └── README
│
├── src/
│   └── main.cpp
│
└── platformio.ini
```

### Rôle des fichiers

**config.h**

Ce fichier contient les définitions des broches et les paramètres matériels du projet.

**main.cpp**

Ce fichier contient le programme principal, les fonctions `setup()` et `loop()`, ainsi que la gestion du bouton.

La directive `#include "config.h"` permet à `main.cpp` d'utiliser les définitions présentes dans `config.h`.

## 3. Configuration des broches

Nous avons préparé les définitions suivantes :

- PIN_BUTTON : bouton physique.
- PIN_JOYSTICK_X : axe horizontal du joystick.
- PIN_JOYSTICK_Y : axe vertical du joystick.
- PIN_JOYSTICK_SELECT : bouton de sélection du joystick.
- PIN_BUZZER : buzzer.
- PIN_TFT_RESET : réinitialisation de l'écran TFT.
- PIN_TFT_DC : commande de l'écran TFT.
- PIN_TFT_SCK : horloge SPI.
- PIN_TFT_MOSI : transmission SPI.
- PIN_TFT_CS : sélection de l'écran TFT.

**Remarque :** la dernière configuration proposée utilise D1 pour `PIN_BUTTON`. Cette broche devra être vérifiée dans le fichier `config.h` avant le branchement physique.

## 5. Mise en place de la détection du bouton

Nous avons préparé un système de détection d'appui avec anti-rebond logiciel.

Les paramètres retenus sont :

- `PRESSED_LEVEL = LOW`
- `DEBOUNCE_MS = 30`

Le système utilise une structure `Button` contenant :
- `pin` : broche utilisée.
- `stableLevel` : dernier état stable confirmé.
- `lastRead` : dernière lecture du signal.
- `lastChangeMs` : instant du dernier changement du signal.

La fonction `justPressed()` détecte un nouvel appui uniquement lorsque le signal est resté stable pendant 30 millisecondes.

Elle utilise `millis()` et ne bloque pas l'exécution du programme avec `delay()`.

L'objectif est d'éviter les détections multiples provoquées par les rebonds mécaniques du bouton.
